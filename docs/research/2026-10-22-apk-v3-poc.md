# apk-tools v3 사전 검증 (2026-10-22)

DESIGN.md D-002(패키지 매니저) 추천의 근거로, apk-tools v3를 실제로 빌드하고
Phase 2에서 의존할 동작(서명 → 색인 → 설치/업그레이드/삭제, 변조 거부, 재현성)을
작은 예제로 확인했다. KEL 결과물이 아니라 검증용 실험이며, 키는 모두 실험 후 버린
임시 키다.

## 1. 빌드

- 소스: `https://github.com/alpinelinux/apk-tools.git` 태그 `v3.0.8`
  (커밋 `44dcdfc255c26a4e19a4a27f66a54169cce5ca72`, 2026-08-31).
  gitlab.alpinelinux.org가 이 네트워크에서 접속되지 않아 GitHub 미러를 썼다.
- 호스트 의존성: meson, pkg-config, OpenSSL, zlib, zstd 개발 파일.
- `meson setup build -Ddocs=disabled -Dlua=disabled -Dpython=disabled -Dtests=disabled`
  → `ninja -C build`: **4.5초**, 결과 `apk`는 748KB이며 `libapk.so.3`, libz, libssl/libcrypto,
  libzstd, libc에만 링크된다.
- 메모: Lua 없이 빌드하면 내장 도움말이 빠진다(`-Dhelp`는 Lua 필요). 크립토 백엔드는
  `openssl` 또는 `mbedtls` 중 고를 수 있다(`meson_options.txt`).

## 2. 소스에서 확인한 사실

- 소스 트리 전체에 `selinux` 문자열이 없다 → **SELinux 라벨링 기능 없음**.
  xattr 처리 코드는 있다(`src/apk_xattr.h` 등).
- commit 훅: `/etc/apk/commit_hooks.d/*`, `/lib/apk/commit_hooks.d/*`가 *pre-commit*과
  *post-commit* 단계에서 실행된다(`doc/apk.8.scd`). → SELinux 라벨 보정(`restorecon`)을
  post-commit 훅으로 붙일 수 있다.
- 신뢰 키: `/etc/apk/keys`의 PEM 공개 키. v3 파일은 공개 키 자체의 식별자로 찾으므로
  파일 이름은 상관없다(`doc/apk-keys.5.scd`).
- 패키지 생성 `apk mkpkg`, 색인 생성 `apk mkndx`, 서명은 전역 옵션 `--sign-key`.
  `mkndx`는 색인에 넣을 패키지의 서명을 신뢰 키로 검사한다(신뢰 키 위치는 `--keys-dir`).

## 3. 동작 검증

ECDSA P-256 임시 키로 `kel-hello` 패키지(파일 하나)를 만들어 확인했다.

| 시험 | 결과 |
|---|---|
| 서명된 1.0-r0 패키지 + 서명된 색인 → 빈 루트에 `--initdb`로 설치 | 성공. `/etc/apk/world`에 `kel-hello` 기록 |
| 1.1-r0 추가 후 `apk upgrade` | `1.0-r0 -> 1.1-r0` 업그레이드 성공 |
| 신뢰하지 않는 키로 서명한 저장소(9.9-r0) | `UNTRUSTED signature` **경고와 함께 저장소 무시**, 설치되지 않음 |
| 색인은 정상이고 `.apk` 파일 1바이트 변조 | `file format is invalid or inconsistent` **오류로 설치 거부** |
| `apk del` | 파일 제거, world 비움 |

주의: 신뢰하지 않는 저장소는 오류가 아니라 경고로 처리된다. KEL의 자동 테스트는 종료
코드만 보지 말고 "설치되지 않았음"을 직접 확인해야 한다.

## 4. 재현성

`SOURCE_DATE_EPOCH=1761091200`을 두고 같은 입력으로 두 번씩 만들어 sha256을 비교했다.

| 경우 | 두 번 빌드 결과 |
|---|---|
| 서명 없음 | **동일** |
| 서명 없음, 파일 mtime을 2030년으로 바꿈 | **동일** (mtime이 정규화됨) |
| RSA-4096 서명 | **동일** (서명까지 결정적으로 같게 나옴) |
| ECDSA P-256 서명 | **매번 다름** (서명에 무작위 값이 들어감) |

시사점: 재현성 비교는 서명 전 결과물(또는 서명 부분을 뺀 내용)로 한다. 어차피 독립
재빌드 검증자는 KEL 개인 키가 없으므로 서명 전 내용을 비교하게 된다. 서명된 파일까지
그대로 같게 만들고 싶다면 RSA 키를 쓴다. 키 알고리즘은 Phase 2에서 이 결과를 보고 정한다.
